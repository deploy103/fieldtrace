# FieldTrace 현장 한 페이지 가이드

## 시작 전 30초

1. 증거 파일은 가능하면 `input/`에 복사하고 원본을 별도 보존합니다.
2. `./run.sh doctor`로 Python과 TShark 상태, 사례 폴더 쓰기 가능 여부를 봅니다.
3. `./run.sh`를 실행합니다. 분석 중 네트워크는 필요하지 않습니다.

## 가장 빠른 흐름

1. 파일 목록에서 번호를 입력합니다. 모두 처리하려면 **전체 파일**을 고릅니다.
2. 형식과 감지 이유를 확인합니다. 이상하면 **수동 형식 선택**으로 복구합니다.
3. 분석 선택 화면에서 그냥 `Enter`를 눌러 **추천 빠른 분석**을 실행합니다.
4. 결과의 **주목할 후보** 번호를 눌러 원문과 `line:N` 또는 `frame:N`을 봅니다.
5. 결과 메뉴에서 검색, 시간순 보기, 보고서 저장으로 이동합니다.

`1` 전체 분석은 사용 가능한 모든 기본 분석을 실행합니다. `2` 직접 선택에서는
쉼표로 여러 번호를 입력할 수 있습니다. TShark가 없으면 PCAP 항목은 이유와 함께
비활성화되지만 텍스트 분석은 계속됩니다.

## 키와 경로

- `Enter`: 화면의 추천 기본값
- 숫자: 해당 항목 선택
- `0`: 이전 화면
- `q`: 안전하게 종료
- `Ctrl+C`: 진행 중인 분석 취소; 이미 저장된 부분 결과 유지

공백·한글 경로를 그대로 붙여넣을 수 있습니다. 양끝에 맞는 `'...'` 또는 `"..."`
한 쌍만 제거됩니다. WSL에서 붙인 `C:\Users\...` 경로만 `/mnt/c/Users/...`로
변환합니다.

## 목적별 직접 분석

- **IP·도메인 요약**: 접속지와 DNS 후보를 먼저 봅니다.
- **HTTP 요청**: method, URI 원문·디코딩 값, status를 봅니다.
- **로그인 성공/실패**: OpenSSH 계정과 원격 IP를 봅니다.
- **실행 명령**: sudo COMMAND 원문을 봅니다. 명령은 절대 실행하지 않습니다.
- **플래그·문자열 찾기**: 후보를 찾은 뒤 반드시 원문 근거를 확인합니다.

후보는 관측 신호이지 침입이나 정답 확정이 아닙니다.

## 문제 발생 시

- **파일이 안 보임**: 다른 폴더 선택 또는 경로 붙여넣기를 사용합니다.
- **형식 미확정**: 수동 형식을 고릅니다. 바이너리를 텍스트로 강제하면 거부될 수
  있습니다.
- **TShark 없음**: `doctor`의 경로·버전을 확인합니다. 대회 중 자동 설치하지
  말고 준비된 시스템 패키지를 사용합니다.
- **부분 분석**: quick의 시간/레코드 예산 또는 손상 줄 진단을 확인하고 필요하면
  full로 다시 실행합니다.
- **취소됨**: 같은 사례를 열어 커밋된 결과를 검색하거나 새 run으로 재실행합니다.
- **상세 오류**: 사례의 `diagnostics/` 파일을 봅니다. 화면에는 다음 행동만 짧게
  표시됩니다.

## 명령형 비상 사용

```bash
./run.sh analyze ./input --profile quick --case ./cases/match
./run.sh search --case ./cases/match --text 'FLAG{'
./run.sh timeline --case ./cases/match
./run.sh report --case ./cases/match --format json
```
